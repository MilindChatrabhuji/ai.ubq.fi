# Portable authority local unit v1

This experimental prerequisite adds constructor-injected admission, access publication, settlement and HTTP transport contracts. It is not installed in the retained Bun server and provisions no resource, route, secret, store or scheduler. Its single synthetic upstream supports fixed-model Responses/chat JSON and Responses SSE. Existing providers, catalog translation, WebSocket/live mapping, admin and native ownership still require later implementation and acceptance.

`AuthorityStore` must provide a strong snapshot and atomic compare-and-swap across the entire coordination atom. Admission, global active account/fingerprint, principal windows, each provider attempt, billing and publication share that atom. A failed CAS rereads every input. Storage unavailability refuses new dispatch; no local authority fallback exists. The isolated durable prerequisite below now supplies a bounded SQLite adapter. Production binding, retention, migration and scale remain unimplemented.

One principal admission survives all provider hops. Dispatch intent is durable before transport and indeterminate transport failures retain their reservation. Each paid hop has its own attempt id, terminal, provider request id and billing record. Subscription-pool proof must be current, model applicable and fingerprint bound before paid reservation and dispatch. Transient failures cannot authorize paid fallback or quota reset. Request quota commits once at the dispatch boundary; semantic completion independently commits kernel quota; actual provider charges survive client interruption. Unknown spend remains pending until a correlated usage observation; immutable terminal replay remains idempotent after that reconciliation.

After a non-final subscription terminal, `reselectSubscription` atomically advances the existing admission only with current strong proof for its captured account and unchanged credential, routing, reset, overage, principal-policy and quota-window fences. The next reservation still checks the resulting global active generation. Principal concurrency counts every unsettled admission across quota windows; a window rollover does not release an outstanding permit.

Publication is access-only and bound to a fixed owner, epoch, account and workspace. A trusted injected verifier establishes token identity/expiry; the contract does not implement JWT verification or obtain credentials. Monotonic generation CAS and precise native refresh ordering fence old publications. Refresh material, arbitrary URL/socket/path, namespace and extra fields are refused. Publication changes the active account's current fingerprint without electing a different account; old in-flight dispatch and proof updates fail their captured binding fences.

The Worker boundary authenticates before admission, bounds JSON input, delegates schema/catalog validation to a fixed capability, and dispatches only a constructor-pinned HTTP destination. The observation adapter must stream one body and bound its parser state; cloning a response can silently buffer unbounded data and is avoided. The synthetic adapter is only a fixture parser, not a production provider translator. Terminal work is attached to the real request lifetime. An unavailable authority during a terminal write leaves the already durable attempt pending; this unit does not claim guaranteed terminal recovery without a persistent external evidence producer.

Pinned HTTP dispatch uses manual redirects and refuses every 3xx response before any second destination or terminal observer. A cleanup write failure preserves the original structured refusal and the last durable admission/attempt state; it cannot refund ambiguous exposure, fabricate delivery or claim successful cleanup.

Producer EOF records `unobserved`, never native `outgoing.finish` or confirmed client delivery. Admission cleanup and semantic/billing dimensions remain separate from that unresolved delivery fact. A real injected observer may later report `delivered` or `interrupted`; no client acknowledgment protocol is added. Billing-pending attempts and missing terminals remain reconcilable and cannot be refunded as known-not-dispatched. Native positive delivery, hosted Worker lifecycle guarantees and complete provider terminal behavior remain unproved.

Validation uses the existing dependency selector with the four new focused test files, strict TypeScript, changed-file ESLint, scoped formatting and whitespace checks. The separate retained-tooling workerd harness imports this actual final entrypoint graph and performs only loopback synthetic requests. Evidence is retained under `cloudflare-redundancy-evidence/2026-10-18/execution/ai-implementation` outside this module. Local fixture success does not establish whole-VPS-loss continuity, a shared production authority, secure credential publication, complete provider/admin parity, Free-tier fit, deployment, canonical integration or live acceptance.

## Durable authority local prerequisite

`DurableAuthorityStore` persists the complete accepted atom in one versioned SQLite row. Constructor-injected synchronous SQL transactions initialize an absent atom and compare-and-swap its revision atomically; no provider I/O or authoritative memory cache enters a transaction. Restart loads the existing row rather than reseeding it. Unknown schemas, malformed nested states, wrong namespace/epoch, unsafe revisions and constructor-bounded encoded state sizes fail closed. The local fixture uses a 256 KiB atom bound; this is a correctness fixture, not a production retention, throughput or Free-tier sizing decision. The global coordination atom is deliberate because global-active selection and multi-principal quota/reset/paid transitions cross records; sharding them would break the accepted atomicity contract.

`AuthorityRpcServer` exposes only the fixed public `PortableAuthority` operations. Data-plane clients receive `AuthorityRpcClient`, not `AuthorityStore`: no raw state snapshot, CAS, generic KV, seed, policy replacement or credential-publication capability crosses this boundary. Policy and access-publication capabilities remain server-owned and are not installed by this unit. The gateway and delivery outbox accept the same public operation signatures structurally, so local and remote implementations need no cast or dummy local store. The RPC is constructor injected and bounded; no product URL, environment variable, secret, Cloudflare binding, migration or live authority selection is added.

The isolated actual-runtime fixture extends the real `cloudflare:workers` `DurableObject` base class, delegates RPC to this implementation, and pins every Bun and Worker client to one SQLite-backed object. Only the owner harness can inspect state or request the fixture crash/rollover controls; the data-plane operation capability cannot invoke them. The local loopback bridge is a fixture transport, not an approved production authentication or network protocol. Actual DO reset after acknowledged dispatch intent and complete runtime restart must retain pending exposure and admission permits; repeated reserve/dispatch/terminal/delivery/settlement and correlated late usage must remain idempotent. Producer EOF remains `unobserved` and may settle independently of billing. An equivalent positive Worker OS callback is not required; actual hosted cancellation/lifecycle and recovery proof remain open.

New source-selected SQLite tests and the paired Bun/workerd runtime evidence are retained under `cloudflare-redundancy-evidence/2026-10-18/execution/ai-durable-authority`. This local adapter neither activates a shared production authority nor closes live migration, independent credential-owner, existing native-handler integration, full-provider/admin parity, scheduler, hosted resource/lifecycle, deployment or whole-VPS-loss acceptance.

The API-key V3, kernel quota V2, Codex routing/capacity and paid-ledger conformance families now share source-owned pure decision functions with the retained native wrappers. Existing consumed wrapper signatures remain; obsolete internal facade exports are removed without changing decision, I/O or CAS bodies. One combined exact-vector graph runs in pinned Bun and actual workerd test mode under deny-all networking, without native APIs, bindings or listening sockets. This source conformance is separate from complete combined native/HTTP acceptance, including the held Codex HTTP case, which remains required on the Linux CI route while the Darwin fixture boundary is uncleared.

## API-key V3 native conformance extraction

The retained `api-key-policy.ts` wrapper now shares its key-independent V3 row normalizers, window/version and absolute-retention math, and reservation/dispatch/release/definite-pre-transport compensation decisions through `authority/native-api-key.ts`. API-only private DTOs in `authority/native-contracts.ts` retain the native string policy version, `-1` sentinel behavior, complete usage-provider vocabulary and existing stored row types. Transition plans name only the policy/window/request snapshots, fixed check sets, resulting rows and their original reset-based retention; they expose no storage key, generic mutation callback, default store, HTTP route or authority capability. These inputs come from the trusted adapter, never a client-supplied quota claim.

The native wrapper keeps authentication, strict live hash-policy projection, physical keys/namespaces, strong reads, explicit H/W/R reservation CAS and R/W dispatch/release CAS, five retries, contention locks, lease scans, response/header decisions, abort handling and request-owned transport-start guard. A reserved identity may be reused; a consumed identity cannot admit new work. Unlimited policies retain dispatch accounting, zero denies, and definite pre-fetch compensation remains distinct from ambiguous transport. Dispatch does not acquire a new hash-policy or lease-expiry fence that the native implementation did not have. API lease expiry remains five minutes; rewrites retain the original window reset plus seven days instead of extending history from the write time.

This extraction does not attach `PortableAuthority` to native requests or supply a durable production adapter. Kernel, Codex routing, paid ledgers, native ownership, admin behavior and Rust work remain in their existing owners. The source-derived conformance packet is under `execution/ai-native-conformance`; extraction-specific baseline, unchanged native fixture comparison, fixed plan/write-set vectors and actual local workerd evidence are under `execution/ai-api-v3-conformance`. This source unit changes no deployed authority, credential, service, scheduler, route or state format.
