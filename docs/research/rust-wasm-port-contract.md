Selectable provider names, dispatch names, and billing names are deliberately separate. The synthetic `ubiquity` route is not an upstream transport. The administrative subscription hash is SHA-256 of the raw account ID; routing hashes use the source `uos_ai`/`codex_routing_account` salt; credential versions include the account, access token and refresh token. WASM retains the native owner's opaque proven fingerprint and cannot invent a new recipe from access-only credentials. Reasoning efforts remain arbitrary advertised strings in downstream schema/catalog work.

The persistence trait specifies one atomic check-and-mutate authority, strong reads, version refusal, absolute expiry and durability before return. It does not implement a store, initialize absent records on read, define a codec migration, constrain all histories to a bounded hot-state blob, authorize independent ledgers, or prove platform transactions. Record-specific retention remains mandatory: paid request logs expire after 365 days; reset ledgers and paid rollups do not inherit that expiry. The persistence adapter must validate stored data and all identity/range fences before making decisions; deriving deserialization for a shared type is not that validation.

Semantic completion, API-key dispatch quota, kernel reservation settlement, paid billing, body drain and actual client delivery remain independent observations and transitions. Source kernel settlement can follow semantic completion before final delivery; API-key usage commits dispatch; interruption does not automatically refund dispatched or billed work. Worker EOF alone is `DeliveryOutcome::Unobserved`, never a native `outgoing.finish` receipt. No type in this foundation derives success, refund, failover eligibility or settled billing from EOF, a timeout, missing data or an HTTP status alone. `model_unavailable` remains a separate active-selection transition and supplies no quota/full-pool proof.

The workspace is `rust/`, with `gateway-core` and the `gateway-worker` cdylib. Rust `1.98.1`, `worker = 0.8.7`, `wasm-bindgen = 0.2.129`, `serde = 1.0.229`, and `serde_json = 1.0.154` are pinned. The matching `worker-build 0.8.7` and `wasm-bindgen-cli 0.2.129` are build tools, not runtime installers.

`gateway-worker/build.rs` establishes a full Git SHA from authentic clean build-time Git metadata and embeds `cloudflare-<full-sha>` as its release identity; missing, corrupt or dirty provenance fails the build. This is compile-time metadata, not a runtime environment override. The actual Workers fetch handler serves the existing health envelope only after release validation. Every other request returns HTTP 503 `rust_port_route_unavailable`, with no provider call, fake model catalog, permissive auth, or origin proxy. This temporary refusal deliberately has no claim to the final route-specific authentication/404/405 parity.

Run `worker-build --release --locked` from `rust/crates/gateway-worker/`. Observed output is `build/index.js` and `build/index_bg.wasm`, plus packaging files and the compatibility `worker/shim.mjs`; this pinned build produced no `index.d.ts`. The generated JavaScript is workers-rs platform glue; Rust owns the gateway implementation. Application startup does not install dependencies or compile. Build output is ignored, while the new `rust/Cargo.lock` is committed. Existing Bun locks are untouched.

## Shared tuple and query delta

Full migration contract version 3 retires provisional JSON-array key identity before persistence or deployment. `tuple_key::TupleKey` is the single builder, validator and comparator for `tuple-v1:<lowercase hex>` identities and their binary SQL sort keys. Typed `KeyPart` supports bytes, UTF-8 strings, arbitrary signed bigint magnitudes fitting the source one-byte length field, IEEE-754 numbers and booleans. Source distinctions include bigint versus number, negative versus positive zero, infinities and canonical positive NaN. Raw decoding retains source-accepted bytes without adding a second normalization rule; the source's structural/tag and negative-NaN refusals still apply. Empty tuples are only valid selector prefixes, never stored keys. No legacy value codec, JSON identity fallback, runtime conversion or data adoption is implemented.

`QueryStore` extends the unchanged `AuthorityStore` read/commit methods. Selectors match the pinned source: prefix alone, prefix plus start or end (never both), and ranges with both start and end. Prefix bounds must be strict descendants; exact-prefix rows are excluded; starts are inclusive and ends exclusive. Empty prefix selects the whole keyspace. Each page uses the shared typed order, optional reverse order, an explicit positive limit and absolute expiry before counting entries. Opaque version/selector/order-bound cursors resume exclusively after the last key and permit a changed page limit; malformed or cross-query continuations fail. A bounded page is not a complete prefix or a cross-page snapshot.

The separate delta's fixtures contain 20 vectors captured from the actual patched `@deno/kv 0.14.0` encoder on 2026-10-18 (source SHA-256 `0abb4eb4ae8f4583df9d6638c00cb6b583e0692a788c7b48601dcae4980f7d70`, captured vector SHA-256 `01c93962af3c4b3f9c591fe388f96dcbb6831b3dc9ceb94f808932b6fe0d302a`). Native core tests, native/WASM check and Clippy, and formatting on the new frozen tree are separate from foundation `be753048401b4e73dabbee53aa9bcb3acd21aefc` receipts. Actual SQLite query, restart/concurrency and whole-application conformance remain the runtime adapter's acceptance surface.
