# Catalog runtime contract v1

Implement the source catalog runtime over the shared QueryStore and gateway-schema projections/cache helpers. The owned surface is this crate only; shared manifests, other crates, original TypeScript, credentials, live stores and deployments are excluded. This module is integration work and does not establish full application or live acceptance.

Preserve exact client-version isolation, source auth generation, current credential fingerprints and existing source revision checks, pool-order union, 5-minute freshness, 24-hour retention, per-version 15-second refresh leases and bounded cold waits. Client ETags hash the final served body. Ordinary models retain the official schema; rich versioned catalogs preserve advertised metadata, including explicit none and custom reasoning strings. Catalog failures are never quota or capacity-exhaustion evidence.

CredentialPublication is supplied by the credential owner and references the existing source records; it contains no secret. CatalogHost resolves fixed typed fetch targets, applies that exact publication's headers, enforces source redirect and observation bounds, and implements request cancellation, clock, randomness and waits. Only the existing owner may implement refresh_codex; its default explicitly reports an unavailable capability. The host records typed Codex response/transport health observations and standalone provider degradation through their existing event owners; an absent capability is explicitly reported by the host. These optional telemetry failures never change catalog serving or create quota proof. No environment lookup, native discovery, OAuth, scheduler or new durable ledger exists here. Provider memo entries are isolate-local, matching the source caches.

Changed Rust paths map to scoped rustfmt, focused cargo test/check/clippy with warnings denied, and wasm32-unknown-unknown check, all on the isolated VPS interface. An explicit diagnostic workspace/lock overlay is noncanonical evidence. Stop at a clean owned commit, passing module checks, exact source/tree/log receipts and a handback of remaining integration/host capabilities. No push or PR is authorized in this lane.

The main Codex and non-Claude discovery bodies retain the source's unbounded read contract; no invented 4-MiB rejection is added. Only a complete cloned single-account observation within 4 MiB and one second may publish single-account eligibility hints. Claude retains its explicit 2-MiB page, 20-page and 8-second bounds. Host cancellation must return through the running request so the lease finalizer settles; dropping the entire future leaves only the source lease TTL as recovery.

CatalogFetch exposes the source timeout as an option: the main Codex fetch has none, other non-Claude providers use ten seconds, and every Claude page shares one absolute eight-second discovery deadline. The adapter uses remaining_timeout_ms at dispatch and retains cancellation through body reading. These reads cannot spend inference credit or establish quota exhaustion.

# Paid routing control bridge contract v3

The controller's paid-control contract and frozen API are `/tmp/ai-rust-paid-control-contract-v3.md` and `/tmp/ai-rust-paid-control-api-v3.md` (API SHA256 `274819c66fecdee82fdc93db11ead393b26a141953d1e31eb55c65846ff8b19b`). This crate now owns fixed Surplus/OpenLux observation and full paid-routing projection publication in the same QueryStore. The existing authority owns the key/DTO schema and exact per-request receipt plus reservation-time checks; the native configuration owner publishes authenticated owner/epoch/configuration and actual credential bindings. No live owner bootstrap, token installation, new ledger or provider inference is authorized here.

`CatalogRuntime::publish_paid_observation` captures owner, configuration, credential and prior observation revisions before awaiting its fixed provider fetch, then publishes only with those same CAS fences. `publish_paid_routing` captures all six mandatory source records before cold provider discovery, reuses current durable observations, replaces the full coarse index, and fences source/control/observation/policy revisions in one atomic commit. Returned publication objects have private fields and grant no paid authorization. The authority's opaque server-owned receipt remains mandatory for every paid admission.

Surplus/OpenLux refresh freshness never becomes route expiry: retained stale observations keep their actual source time and optional source-defined deadline. Missing OpenLux discovery retains the source configured-plus-known-Codex fallback; an observed empty list remains distinct. Surplus needs its actual route and price/tool facts. The coarse index covers possible ordinary and source-authorized pinned synthetic plans in Surplus-to-OpenLux order; it cannot authorize endpoint, tools or a synthetic override. The authority reuses the provider planner on the exact server-normalized request context and current persisted facts. Whitelist advertisement does not add a paid runtime allowlist.

The response capability carries optional normalized provider correlation, exact-token expiry status and response receipt time for source health attribution. None means unknown. Native owner/configuration integration tests and their gateway-native/gateway-auth dependencies are limited to non-WASM test targets; the production portable closure must exclude gateway-native.
