# Admin runtime integration contract

Module m12, contract v5, source base `412166e856721c285ff22f3fe2255e5dbe83ac7a`. Version 2 adds the root-authorized typed native streaming response integration, invalidating the earlier unconditional Supervisor follow refusal and its test. Version 3 reconciles the source persistent ordinary deletion guard and the owner-specific local-development retry/completion marker, invalidating earlier release-on-refusal and retained-history assumptions. Version 4 consumes the root-authorized shared native request/stream types and descriptor validator, invalidating the earlier duplicate in-process native request type. Version 5 separates readonly native brief context from the final Rust-generated public brief response; direct context forwarding is stale. This crate implements `gateway_admin::AdminHost`; it does not replace `AdminService`, create a second authority, or claim full application acceptance.

Construct `AdminRuntime { store: &query_store, host: &auth_host, capabilities: &bindings, config: &runtime_config }` and pass it as `AdminService.capabilities`. The root-authorized exact predecessors `888f0816d845d4b1408dc09c9132622846578fee` and `0eaf3917f42543534bcd2da42b0253377024f92f` supply the shared finish/abort deletion hooks and native protocol; both hooks are wired and `capabilities::NativeRequest` aliases the shared `gateway_auth::native::NativeReadRequest`. `RuntimeConfig.claude_allowed_key_ids` is explicit existing bootstrap configuration; the crate never discovers environment variables or credentials. Every `execute` call requires an authenticated admin; `is_super_admin` is not a gate. Keys, passkey users and kernel public keys remain in `gateway-admin`.

Public `SupervisorBrief` dispatches the dedicated `RuntimeCapabilities::supervisor_brief(SupervisorBriefTarget, Context)` operation, which composes readonly native context with the source's fixed Rust summarizer. Its response must contain the exact final public fields for the selected source/thread, with transcript metadata only. Raw context/turns, unexpected fields, stream descriptors and misleading no-transcript model metadata fail closed. The no-transcript branch performs no model call. Actual prompt construction, response parsing and bounded redaction belong to the supervisor-data owner; the Worker binding supplies the fixed Cerebras inference operation.

Native follow responses pass the shared `NativeRpcResponse::validate_for` contract against the original finite request. The runtime preserves `AuthResponse.stream`, rejects a successful JSON-only follow response and rejects a descriptor for another source, thread or cursor. These tests establish descriptor fidelity only; actual SSE stream acceptance remains with the real native/Worker fixture.

Every unbound method of `RuntimeCapabilities` returns 503 `admin_capability_unavailable`. Capability arguments have finite named operations; none accepts an arbitrary URL, command, SQL query, filesystem path or Bun gateway endpoint. Some source documents and the capacity-rollup query remain structured input to their named owner; this crate does not claim their domain validation is implemented. Only the final `RuntimeCapabilities::supervisor_brief` composition and `CodexRequest::RunCacheExperiment` can spend provider credits only when an authorized real host binds them; no such call occurs in this module's checks.

## Common Claude roster API

`claude::account_store_key()` names the unchanged source tuple `['uos_ai','claude_code_accounts','v1']`. `AccountStore`, `AccountBinding`, `Credential` and `Workspace` preserve the source v1 fields; credential Debug output is redacted. These are secret-bearing storage types and must never be serialized into admin responses. `read_roster(store, now)` returns an optional `RosterRead { roster, revision }`; `load_roster(store, host, &Bootstrap)` performs source absent-only singleton/environment bootstrap with exact legacy-revision CAS and twelve retries. A present empty roster is authoritative and never resurrects a legacy or environment credential.

`update_account`, `select_account` and `remove_account` write that same source roster with source limits, duplicate checks and expected-binding fences. The fingerprint is SHA-256 of the source JSON tuple `[credential.kind, credential.secret, workspace.id or null]`. Updating only metadata preserves account cohort and evidence generation; changing the credential/workspace fingerprint rotates both. `active_binding`, `same_binding` and `current_binding(store, binding, now)` expose selection and the exact current roster `RevisionCheck` for the caller's dispatch CAS. They do not fabricate current-credential validity, model eligibility, quota exhaustion or full-pool proof. The authority owner supplies those proofs using the exact source quota rows.

## Paid policy and deletion

`paid_key_policy` uses the immutable full Codex snapshot; it never estimates exposure from the compact runtime catalog. A typed pricing observation must advertise only current Codex models, a positive quota-per-credit and positive finite coefficients. Every allowed model needs a finite full-context exposure; otherwise initialization fails before a key write. The pricing capability performs metadata reads only and issues no inference or purchase. `gateway-admin` preserves existing pricing on already-enabled updates and disabling; only creation or a false-to-true change initializes it.

`prepare_key_deletion` claims the common `paid_deletion` guard before scanning actual paid attempts, windows, pending markers and the reconciliation gate. The existing authority's paid-admission CAS observes that same guard, preventing a concurrent new attempt. Pending, unresolved, corrupt or unknown billing refuses. Ordinary guards persist on refusal and success in the source shape `{created_at_ms}`. Only the fixed `local-development` key has a nested owner/completion marker: a known pre-ID refusal conditionally releases that owner to null while retaining the guard; a successful completion requires the exact owner revision and an absent-ID CAS.

Settled paid requests/windows and reconciliation leases are removed before the ID CAS through exact observed-row and retained-guard checks. The returned actual guard/gate/lease fences join the same key/hash/policy/audit deletion transaction. `finish_deletion` removes only the key's source current/legacy request logs, V2 counters, V3 usage and legacy usage/daily singletons in bounded pages after the ID is absent, preserving every foreign key and retained rollup. `abort_deletion` implements only the known local-development ownership release after a fresh revoked-ID read. The shared `AdminHost` completion/abort hooks must call these implementations; a default unavailable hook cannot substitute for cleanup. There is no automatic resume after a source 404 or a guessed all-clear ledger.

The shared `gateway-admin` correction removes its stale preclaim guard check only for DELETE, requires the new nonempty guard revision, preserves the raw NDJSON/empty experiment body, and materializes effective paid-enable inputs. This crate does not modify that owned source; integration must include the native/admin worker's accepted correction.

## Claude isolate generation

`claude_generation::StateGeneration` is a cloneable `Rc<Cell<u64>>` handle owned once per isolate and source KV object, not once per request or durable authority row. It starts at zero after a new isolate/KV object. Its source-number increments stop at 2^53, matching JavaScript `number + 1`; it never wraps. Only successful source credential stores, credential clears (including an absent credential), and workspace stores call `record_success(StateChange)` even for identical input. Failed operations, reads, generic roster changes, and account selection do not call it. Roster/evidence revisions remain separate durable fences.

Capture `snapshot()` before asynchronous account/workspace reads and require `snapshot.is_current()` after every awaited boundary. `catalog_identity(&snapshot, account, credential, workspace_id)` returns the exact source SHA-256 JSON tuple `[account_id or null, account_cohort_id or null, kind, secret, workspace_id or null, numeric_generation]` or `None` for a stale or foreign-owner snapshot. Its synchronous hash introduces no await. Carry the same generation owner/snapshot into the catalog publication host; catalog discovery separately checks current durable binding and the resulting identity after I/O. An environment-only resolution has null account IDs and its unchanged zero generation, not a synthetic account. The Worker must retain one handle in its isolate-local state and share clones with the actual successful mutation owners; this crate does not discover or install a global owner.

## Shared Claude access policy

`claude_access::{ClaudeAccessPolicy,PolicySource,AccessRead}` and `load_policy(store, auth_host, explicit_seed_ids, &comparator)` expose the actual source policy plus its exact `RevisionCheck`; this is data, not a forged admin invocation or cohort proof. The comparator is the trusted source `localeCompare` host operation. `parse_ids` and `parse_policy` share the admin route's parser; insertion order survives before stable collation so equivalent Unicode labels retain source order. Bootstrap occurs only on absent state, uses the explicit trusted seed, and retries at most eight CAS conflicts. A present empty `kv` list denies access, malformed state never falls back, a missing comparator remains explicit unavailability, and update times must be positive safe integers. Callers join the returned check to their current-admission transaction; a load alone cannot authorize a later superseded generation. The existing admin GET/SET path now uses this same parser/loader.

The fixed admin-error reader accepts ordinary JSON and explicitly marked ProfileV2 rows, preserves source UTF16 strings and object keys directly in the SourceJson response, and rejects ProfileV1 or unsupported typed fields rather than reinterpreting them as JSON. Admin authorization, request-limit validation, reverse prefix visitation, historical interruption suppression, full 5xx aggregation and independent retention/log-size diagnostics retain their existing owners and sequencing. No dependency on observability is introduced. Wire assertions inspect response bytes rather than assuming the response body is a Value; raw-string fixtures inspect code units directly.
