# Extras runtime

Contract v3 implements the source embeddings, retained jobs, image orchestration and SystemOne routes from base `1b7b9737bd8c7dc11fde4757371ed211ae919ab2`. The exact public surfaces are `POST /uos/embeddings`, `POST /uos/embedding-jobs`, `GET /uos/embedding-jobs/{id}`, `POST /v1/images/generations`, `POST /v1/images/edits` and `POST /v1/systemone`. The HTTP adapter supplies the already authenticated principal, original request context, bounded raw byte count, parsed JSON or normalized multipart fields/files; it owns HTTP, CORS, request IDs and body transport.

`ExtrasRuntime<S: QueryStore, H: ExtrasHost>::handle` returns buffered JSON, response headers and independent observed usage, semantic, kernel-disposition, provider-health and private upstream-error evidence. Only `response.body` is serialized to the client. Provider/transport errors never become quota exhaustion evidence. The host maps the typed Voyage, SystemOne and Codex-only image-child operations to the existing original m14 admission handle; child calls never begin another quota/accounting lifecycle. The m10 resource permit remains with the outer response owner until its actual lifetime settles.

Voyage preserves the fixed 128 inputs, 20,000 UTF-16 units per input, 100,000 total units and 10,000 estimated UTF-8-byte/4 tokens per chunk, with a 20-second handler deadline. Its shared source budget is 3 requests and 10,000 tokens per rolling 60-second window, protected by CAS. Deduplication keeps original result ordering. The cache uses source profile keys, canonical tuple keys, stable FIFO pointers and global oldest-first quota eviction, with no invented TTL or per-principal cap.

The embeddings idempotency journal has the original principal/key/fingerprint hashes, 60-second reservation lease, 7-day ledger and 8-day response chunks. Dispatched uncertainty, stale dispatches, partial success and incomplete replay fail closed as indeterminate. Successful replay is an explicit header and releases kernel usage rather than charging another generation.

Retained jobs keep owner-bound lookup/job/input keys, 24-hour TTLs, 30-second CAS leases and poll-driven retries. The host performs actual AES-256-GCM with source SHA-256 key derivation, 12-byte random IVs and a 16-byte authentication tag; input rows retain only the original base64 ciphertext shape. Stable API-key IDs or kernel repository identities take precedence over rotating bearer text. No scheduler or hidden provider request is introduced. Native tests use pinned dev-only RustCrypto AES-GCM; production uses the Worker WebCrypto capability, with no encryption bypass.

Images validate through the shared opaque parsed-input factory before host-model resolution, then use exact child IDs, one original dispatch ownership scope, concurrent children, first-failure sibling cancellation, all-child settlement, source header aggregation and first-image-per-child output. No paid image fallback is authorized. SystemOne preserves the typesafe model namespace, question/body limits, actual provider selection, fixed OpenRouter endpoint and source usage/error/health behavior.

Source-derived native tests cover idempotency replay/conflict/stale dispatch, partial progress, budget contention/wait/retry, cache eviction across profiles, encrypted job ownership/rotation/tamper/expiry/races, poll-driven retry, SystemOne control/error/usage behavior and image child correlation/settlement. Required scoped fmt/check/test/clippy and wasm32 checks run on immutable VPS snapshots. The platform's real HTTP, cryptographic, transport, telemetry and original-admission integration acceptance remains a separate required surface.
