# Gateway authority

This crate ports the domain transitions extracted from source e706343d4a5f11890e39ab3599bdc04e154b1fba. The shared gateway-core AuthorityStore contract requires strong reads and one atomic durable commit of every checked revision and mutation. A successful store commit includes the platform durability barrier. A CAS conflict discards the candidate and rereads the complete decision; provider I/O and streams never enter a transaction.

The bounded dc6be2c3b59188b0e4135b80cb4f0f6b492e232c source update is also included: kernel reservation reset must follow creation, lease expiry must follow reservation, released reasons cannot be whitespace, and every indexed active reservation must match its window reset identity and aggregate. Restore-specific legacy import/no-overwrite and orphan detection remain native/migration ownership; this crate never opens or converts a legacy database.

The platform supplies TokenSource with unpredictable unique owner/probe/revision tokens. Live reset paths additionally require Authority::with_clock and a trusted AuthorityClock so the deadline/day/lease is checked again after awaited reads; a missing or backward clock refuses submission. Record revisions remain opaque. Per-record schema versions and absolute expiry are validated; malformed or unavailable state fails closed. Separate records hold active coordination, outstanding indexes and retained history. The crate imposes no whole-history snapshot cap, eviction policy, timer, cron or alarm.

Domain rows explicitly use StoredRecord::json and json_value; ProfileV1 records are refused without inspecting or guessing their JSON-looking shape. A separate migration must prove JSON-only values and translate the application schema before business-state adoption. Portable window indexes and kernel/paid transition DTOs are not interchangeable with raw legacy records; raw profile validation and index reconstruction remain migration responsibilities.

The routing module owns the global active subscription, selected-cohort proof, independent quota classes, current credential/generation fences, narrow learned model entitlement and bounded probe leases. Empty pools, unknown/model errors and held leases do not become authoritative pool exhaustion. Quota-only proof permits banked-reset evaluation; mixed quota/current-invalid proof permits ordinary paid continuation. Proof is re-evaluated against the current clock and exact stored revisions at use time. Direct paid models and disabled Codex retain their separate existing routing path.

Claude paid continuation uses a separate opaque proof from strong reads of the existing source roster and account/cohort quota rows. It requires every current binding's fresh applicable auth-invalid or exact-model quota proof, validates credential/workspace fingerprints, and includes all revisions in the same paid reservation CAS. The platform must supply Authority::with_clock; expiry is checked again after awaited ledger reads, including retained pending attempts. Missing, empty, no-active, malformed or incompletely proven pools never fabricate exhaustion. Proofs expose no secrets or client deserialization, do not replace Codex authorization, and introduce no new persisted state or TTL.

The quota module keeps API-key dispatch charging separate from kernel semantic settlement. One ApiReservation survives every retry/provider hop. The runtime resolves a deferred reservation before actual provider dispatch, calls dispatch_api_key once per attempt, and marks transport intent immediately before fetch. A known pretransport cancellation can compensate; client cancellation after transport cannot refund it. Kernel terminal intent is durable, idempotent, independently renewed and settles only its original window. The source default kernel window is seven days.

The paid module retains one PaidAttemptId for each provider hop under the original RequestId. Existing pending attempts are returned as PaidAdmission::Existing so an integration cannot mistake ambiguous retained intent for permission to issue another paid request. Each new attempt persists dispatch intent, reserves integer exposure under the current key policy and versions its reconciliation gate before transport. Semantic terminal, correlated provider billing and delivery remain independent. Metered settlement requires exact upstream request id; Surplus settlement requires its exact reservation and preserves authoritative buyer microcredits. Actual spend can exceed reserved exposure and remains recorded. Pending/unresolved exposure is never refunded because of timeout or client cancellation.

Paid reservation also requires an opaque exact-request routing receipt from the same authority. The fenced v2 projection refers to authenticated fixed owner/configuration and provider observations, plus current source revisions. The actual source planner rechecks client endpoint, tools, current synthetic alias and pinned provider before both new and existing reservation CAS paths. Retained stale source observations remain usable without an invented refresh expiry. The runtime must compare the receipt's protected owner/epoch/configuration/credential identity to its owned access fence before reservation and transport. An unfenced v1 row or missing owner custody refuses admission; metadata DTOs do not confer a write capability and this source work installs no live owner.

Codex account-model hints retain the original raw-account-ID source shape. The authority verifies normalized pool identity and version against the current raw credential row, then derives the eligible cohort from the current source provider selection and uses a transient hash-keyed view. Learned unsupported models update only the raw account's model timestamp map, preserving source catalogs and other metadata. A normalized model view is never serialized into that source key.

The reset module accepts complete typed observations from the authenticated approved native provider boundary; it does not create provider authority or perform redemption. Live selection, immediate first-request submission, account/window deduplication, owner leases, monotonic fences, per-account UTC-day budget and final submit renewal remain separate steps. An absent reset configuration has a zero daily cap and therefore declines live spend until an explicit cap of one is stored; historical shadow decisions are never consulted or rewritten by live selection. Submitted/unknown recovery is lookup-only even when live policy is disabled. Ordinary overage fallback holds a scoped account/class lease without electing a different global active account, and the per-account allow setting is a hard gate. A stale verified reset cannot clear a newer quota generation; its explicit bounded recovery path cannot consume another credit.

API and kernel rows expire at their original window reset plus seven days. Paid request rows expire at creation plus 365 days and paid windows at reset plus 365 days; rewrites do not refresh those deadlines. Paid rollups, unresolved indexes, reset redemption/day records and owner decisions have no invented TTL. Event owners call due_paid and reconciliation lease methods; no periodic work is introduced.

Tests use a deterministic transactional fixture that enforces compare-and-set, logical expiry, checked mutations and unique writes, including actual thread races. They prove domain transitions only. They do not prove Workers SQLite persistence, native ownership, migration, hosted delivery, production data adoption or live inference. Those acceptance surfaces remain with their assigned runtime, native and delivery modules.

Public policy and pool types are shared with gateway-admin/native through this crate's key helpers. All key helpers use the controller's v3 shared TupleKey/ScalarKeyPart codec; the provisional JSON-array convention is retired with no compatibility fallback. Workspace membership and Cargo.lock are single-writer controller responsibilities. Rust compilation and formatting run on the VPS build lane, never implicitly on this Mac or during application startup.
