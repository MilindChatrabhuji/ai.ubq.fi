# Offline state adoption

For the Workers Free migration lane, [`CORE_STATE.md`](CORE_STATE.md) defines the measured bounded operational-core profile: 2,317 selected source rows, 5 derived rows, and 4,640 Durable Object row writes. It excludes historical logs, replay, analytics, incidents, telemetry gates, error logs, and historical usage while retaining current auth, routing, capacity, quota, reset, and accounting state. The profile is offline-only and does not weaken the custody or activation gates below.

This library accepts a private full logical capture with explicit original revision and absolute expiry on every row. It does not open a Bun/Deno database, read credentials, refresh tokens or activate a new owner. Ordinary profile NDJSON has no expiry metadata and is not a complete production-state capture. The existing target owner must stop source and target writers and withhold ordinary target traffic until adoption completes; a library over `AuthorityStore` cannot prove those OS conditions or fence arbitrary uncoordinated new-key writers.

`prepare(&PrivateCapture, &SourceDateHost)` validates the codec, full schema inventory and coupled indexes; `adopt_empty(&same_query_store, &prepared)` performs one atomic transition with absent-key checks and persistent inverse metadata. No existing target is overwritten. The target must be the actual common authority used by auth/admin/admission, not an independently live account ledger. Native current credential/publication ownership and proof capabilities are not imported from snapshots.

`export_latest(&quiesced_store, now)` reads current state, preserves post-adoption writes and deletions, inverts source/runtime schema differences and revalidates the complete latest source/index inventory. It never reads a stale backup. Identity rows do not duplicate historical provider/session secrets in sidecars. Original source-only fields are retained only for reviewed non-secret transforms. Keep private export artifacts and their hashes in the task's private evidence custody; never return them through an ordinary admin response or log them from a live service. See `TRANSFORMS.md` for exact families and remaining owning-runtime schema dependencies.

On the prepared VPS, under the same compiler lock, two Cargo jobs, frozen dependency graph and denied-network fixture boundary, run `cargo run --locked -p gateway-migration --example offline-fixture` and capture stdout to a task-local JSON artifact. This command accepts no arguments, only includes `tests/fixtures/offline-source.json`, creates fresh isolated SQLite files, restarts the actual store, authenticates its synthetic key, performs an actual post-restart admission write, exports the latest source state into a new inverse destination and proves logical equality. It opens no pre-existing database and makes no provider request. Temporary SQLite fixture files are removed after settlement; the captured JSON is the reproducible forward/latest/inverse artifact. This is an offline runtime fixture, not a production conversion command or activation receipt.

Source Date normalization uses the finite `gateway_admin_data::profile::SourceDateHost::source_date_value` raw input hook on `SourceDateHost` for arbitrary source-accepted Date inputs; constructor-bound runtime/locale/timezone semantics are required. The retained UTC and America/New_York Bun 1.4.0 goldens demonstrate why a timezone or byte-collation guess is unsafe. The actual Worker host binding and full combined workerd/native/UI receipts remain with their owners.

Once Rust-only owner/configuration/pool/replay state exists, `export_latest` refuses source-only output with `migration_control_custody_required`. Use `export_rollback_bundle` with exact release/tree/WASM/native artifact identities; its separately private `rust_controls` retains current tuple identity, explicit value encoding, revision and absolute expiry for the owner/configuration/observation/pool and nonce rows. It is evidence, with no restore API and no proof or ownership constructor. The source portion never receives Rust-only rows. The operator must separately retain a consistent stopped native nonce SQLite plus WAL/SHM capture and bind its hash, then reconcile current owner epoch/configuration generation/key fingerprint and every current replay fence before any resumption. Never restore an older nonce registry under current transport custody, auto-rotate keys/owners, or treat inverse data as a replay/auth reset.

Private capture JSON must be parsed/serialized directly from/to bytes or strings. `SourceEntry.key` and `.value` are validated `SourceJson` leaves: passing the capture through `serde_json::Value` cannot preserve unpaired UTF16. `from_source_profile_with_host`, `to_source_profile` and `normalize_source_import_line_with_host` provide the raw profile boundary. The inverse uses explicit source-accepted representations for negative zero and invalid Date; this is a full logical capture, separate from the ordinary lossy profile writer. The v3 private adoption metadata refuses older versions and keeps no historical identity keys or values. Effective business-schema readers must explicitly support ProfileV2 before UTF16 business rows are accepted; a retained-data codec test alone does not establish that runtime binding.

Native complete capture v2 is separate from ordinary profile capture v1. `NativeCapture` carries exact raw tuple bytes, decimal SQLite version/sequence integers, absolute native expiration, a pinned Bun codec/schema and empty native queues. Values explicitly select `source-graph-v1`, `counter-le64` or `bytes`; VM bytes are never guessed. `prepare_native` binds identity-free business values to the existing schemas and retains generic graph data with its actual `SourceGraphV1` query accessor. Unsupported business aliases/cycles refuse before the atomic write. Post-adoption graph updates, backing-buffer offsets, aliases, deletions and raw non-UTF8 tuple identities survive restart and latest inverse. Unchanged rows keep their original native revision; updates/new rows receive one deterministic next SQLite version with ordered sequences, and deletion alone advances the global revision. This is an explicit offline revision transform, not a fabricated source versionstamp.

Managed Codex refresh material is rejected by ordinary and native common-candidate ingestion. `sanitize_native_capture` is a trusted offline/native preparation step using a configured `NativeCustody` host and the constructor-only `ManagedAccessProjection`. It independently checks fixed local owner/home, source revision, full native generation and exact credentials before producing access-only candidate rows. No full credential sidecar or historical source key is retained. `export_native_with_custody` rereads the current local owner, checks both physical and access-only generations, token/account/time and current source revision, and refuses drift across the await. Its opaque local result can restore a full managed source row only to private local custody. A new stopped-source revision registration is required before re-adopting that result. `export_native_rollback_with_custody` additionally retains current private control/replay evidence; neither operation authorizes live activation.

Source sessions receive the owning auth module's secretless revision index in the same adoption transaction. The index is private operational custody, never an input source row. Pending live-call retirement markers are also private custody; any suppressed mapping stays only in that bundle and is omitted from legacy source output so it cannot become joinable after rollback. Unknown/malformed markers refuse the export. Source-only exports refuse when this custody is present.

`cargo run --locked -p gateway-migration --example native-offline-fixture` accepts no source/target/credential arguments, uses only the committed synthetic native fixture, restarts the common SQLite authority, authenticates and admits its fixed key, performs a latest alias-preserving write and emits the inverse native capture. `tests/support/native-capture-fixture.mjs` is the task-only pinned-Bun capture/restore oracle; its frozen source-module bindings and the narrowly labelled Buffer extension are recorded in the external receipt. The native-owner fixture uses the real configured `UnixOwnerTransport` against two synthetic task-local auth files, preserves siblings, handles an advancing physical generation with unchanged access, rejects stale custody and re-adopts a newly bound inverse.
