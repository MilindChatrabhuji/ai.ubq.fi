# State adoption contract v2

Module m20 starts at `fbe045d1040b9de4bc1de9b0b7ba7dec97177c32`; first-party source semantics come from `ba5ef05e74e7684589981c9b2a22518137a964f1`, reconciled with accepted `6d4d4790a7c06514b92938ff677dbfd52764461d` and its 37-path extraction matrix. The input is a complete offline capture with explicit typed profile values, source versionstamp and absolute expiry for every row; ordinary profile NDJSON omits expiry and cannot establish a full-state capture. Capture and adoption require stopped source writers and an unopened, empty, quiesced target under its existing owner; this library cannot prove OS/process stoppage. It writes only through that target's existing common `QueryStore`/`AuthorityStore`, never a second ledger. Runtime activation remains outside this module.

Every accepted source row receives one reversible mapping record containing revision, expiry, runtime digest and transform ID; identity values stay only at their actual source key, avoiding duplicate historical provider/session secrets. Non-secret transformed rows retain source-only fields in private common-store metadata. Untouched source records roundtrip exactly. Inverse reads the latest runtime records, preserves updates/deletions and removes only documented derived indexes. It refuses unknown Rust-only schemas and missing/ambiguous current mappings. Original database and credentials are never opened or changed. A source snapshot cannot mint `CohortProof`, `ClaudeCohortProof`, `PaidRoutingReceipt`, native ownership or current credential authorization.

Adoption commits the complete prepared target rows, derived indexes and reversible mapping/manifest in one common-store atomic transition with absent-target fences. A refused/corrupt capture writes nothing. Existing target data is not overwritten. The caller must keep the target inaccessible to ordinary writers until the transaction finishes; `AuthorityStore` alone cannot fence arbitrary new-key phantoms or prove an OS-stopped owner. Runtime tests use an actually isolated persisted fixture store, restart it, call existing auth/query/admin/admission consumers, make accepted mutations and inverse-export the latest state. Production sizing, capture proof and activation are separately bound to the final real host adapter.
