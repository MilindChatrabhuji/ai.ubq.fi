# State adoption contract v7

## Bounded core-state profile

The Workers Free migration lane uses the separate bounded profile in [`CORE_STATE.md`](CORE_STATE.md), not the complete-history default described below. It selects the operational core from the same stopped capture, excludes historical usage/telemetry/replay/error/analytics families, preserves current auth and quota state, and refuses adoption at or above 100,000 Durable Object row writes. The complete-capture contracts remain authoritative for any full-history or rollback lane; the bounded profile does not weaken their custody, source-immutability or activation rules.

Module m20 starts at `fbe045d1040b9de4bc1de9b0b7ba7dec97177c32`; first-party source semantics come from `ba5ef05e74e7684589981c9b2a22518137a964f1`, reconciled with accepted `6d4d4790a7c06514b92938ff677dbfd52764461d` and its 37-path extraction matrix. The input is a complete offline capture with explicit typed profile values, source versionstamp and absolute expiry for every row; ordinary profile NDJSON omits expiry and cannot establish a full-state capture. Capture and adoption require stopped source writers and an unopened, empty, quiesced target under its existing owner; this library cannot prove OS/process stoppage. It writes only through that target's existing common `QueryStore`/`AuthorityStore`, never a second ledger. Runtime activation remains outside this module.

Every accepted source row receives one reversible mapping record containing revision, expiry, runtime digest and transform ID; identity values stay only at their actual source key, avoiding duplicate historical provider/session secrets. Non-secret transformed rows retain source-only fields in private common-store metadata. Untouched source records roundtrip exactly. Inverse reads the latest runtime records, preserves updates/deletions and removes only documented derived indexes. It refuses unknown Rust-only schemas and missing/ambiguous current mappings. Original database and credentials are never opened or changed. A source snapshot cannot mint `CohortProof`, `ClaudeCohortProof`, `PaidRoutingReceipt`, native ownership or current credential authorization.

Adoption commits the complete prepared target rows, derived indexes and reversible mapping/manifest in one common-store atomic transition with absent-target fences. A refused/corrupt capture writes nothing. Existing target data is not overwritten. The caller must keep the target inaccessible to ordinary writers until the transaction finishes; `AuthorityStore` alone cannot fence arbitrary new-key phantoms or prove an OS-stopped owner. Runtime tests use an actually isolated persisted fixture store, restart it, call existing auth/query/admin/admission consumers, make accepted mutations and inverse-export the latest state. Production sizing, capture proof and activation are separately bound to the final real host adapter.

Version 3 consumes the material m22 source-shaped R/C schema contract; earlier temporary flattening/refusal code and its DTO evidence are stale. The m22 committed API predecessor and integrated combined runtime gates are required before this dependency is accepted. Private inverse paid rows use source `request_id` as the physical attempt ID and preserve a distinct Rust original request in the explicit offline `original_request_id` field when they differ; no public OpenAI wire field or source backend is changed, and no request is replayed by migration.

Version 4 changes private adoption metadata to v2: per-row mapping keys use SHA-256 digests; the manifest keeps only a count, with no global list of historical keys, and identity mappings retain neither source key material nor source value copies. Current surviving keys are reconstructed through the shared tuple codec (including bigint/bytes/boolean/number types). Deleted or expired session/credential rows cannot leave historical plaintext in migration sidecars. Earlier v1 metadata receipts are stale; no live Rust state exists to convert or silently adopt.

Version 5 requires explicit expiry fields in private capture JSON, verifies the complete current mapping inventory checksum, and separates Rust owner/configuration/pool/replay custody from source-only rollback. A source-only export refuses rather than dropping those operational rows. The private bundle binds exact current release/tree/WASM/native artifact identities and separately held native nonce-capture identity; it has no restore or authorization API. Derived Kernel defaults must match the current source defaults or inverse refuses policy loss. Source capture/adoption and inverse fixture gates are stale until rerun against the committed v5 tree.

Version 6 consumes the frozen shared UTF16/SourceJson codec and source TextEncoder key boundary from canonical `9cc05985449502adecdf6718118b30526b4f919a`. Private capture key/value leaves use validated raw source JSON and emit actual JSON strings without a `Value` roundtrip. Values requiring non-scalar UTF16 select explicit ProfileV2; ordinary JSON and ProfileV1 remain unchanged. The existing tuple codec folds only source string keys through its documented TextEncoder USV conversion, while value code units remain exact. Source collection duplicate/property ordering follows the source realm. The finite `SourceDateHost::source_date_value` hook accepts original validated JSON; scalar inputs delegate the existing host and raw-only inputs report named unavailability without a host override. Generic retained-data fixtures prove this codec path; UTF16 in effective business schemas still requires the corresponding owning runtime reader and validation, and is refused where only a Value reader exists.

Version 6 also bumps private adoption metadata to v3. Non-secret transformed source sidecars store an explicitly encoded raw JSON document string; identity sidecars still erase both keys and values. Full capture output preserves negative zero via the source-accepted number string `-0` and invalid Date via an omitted Date value. The ordinary profile writer remains unchanged: its JSON.stringify-compatible outputs collapse negative zero and encode invalid Date as null, so those ordinary forms are not reversible full captures. Source-oracle fixtures retain that distinction. Earlier v2 metadata/source receipts are stale for this v6 tree; no persisted/live state exists to convert.

The source profile binary representation retains the whole backing buffer and byteLength but no view offset. Private full capture therefore requires explicit binary byteLength equal to the decoded backing length, recursively through containers; partial-view profiles refuse before adoption rather than silently changing the view. A production capture producer must preserve or explicitly refuse original partial views using a separately reviewed full typed capture/restore binding. No ordinary profile reader semantics are changed by this stricter private-capture completeness check.

Version 7 adds explicit native capture v2 and private adoption metadata v4. Raw tuple bytes, native integer revisions, fixed VM graphs, LE64 counters and byte payloads remain separate; arbitrary graph-looking JSON is never inferred. Generic retained rows preserve exact graph identity, ordering, backing bytes and view coordinates. Effective business rows use the reviewed source-to-runtime schema normalization and canonical object-field ordering, refusing graph identity that their owning readers cannot consume. Native inverse uses the latest record rather than an original graph sidecar; one next native version with deterministic sequences represents accepted runtime writes and deletions. Profile-only v1 remains available with its explicit completeness refusals.

Version 7 separates full managed local capture from the access-only common candidate through fixed native custody. Physical native and stored-access generations retain distinct meanings, and latest local reconstruction requires both plus current owner/source fences. Session revision indexes and pending live retirement remain current private control evidence; a pending mapping is omitted from legacy source data and preserved separately. Earlier v6 full-capture/whole-runtime claims do not cover this graph/custody extension. No live database, credential, runtime activation, owner rotation or deployment is authorized by these source/fixture APIs.
