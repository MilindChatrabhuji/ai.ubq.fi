# Routing runtime contract

Contract v4 adds the source model-availability gate to the receipt-bound paid credential fence and aggregate extras admission lifecycle: source `7cc83d404adf4dda7e7e842b38b07548c2262dce`, integrated predecessor `2dfede8510b5bc76865230133821005d4a1289fc`. Earlier policy receipts are stale for this model-gate correction. This crate composes the existing domain authority and provider wire policy. It owns one API/kernel admission across all attempts; m10 owns the separate finite process permit. The Worker owns HTTP, body readers, SSE decoding and actual delivery observation. All inputs, store and host values are owned so a session can live in a static stream/finish future. No environment discovery, networking, credential refresh, second quota ledger, periodic scheduler or backend relay belongs here.

Public seam agreed with m05: `begin`, `next_attempt`, `before_dispatch`, `transport_started`, `refusal`, `observe_terminal` and `finish`. Prepared attempts own the existing m04 `PreparedRequest` and exact server-created attempt identity. The caller reports NotStarted versus Started and may request another attempt only before semantic commitment. Errors retain typed status/body and headers; raw upstream response bodies remain Worker-owned. No cached or caller-supplied text is full-pool proof.

Source-currency seam v1 requires `AttemptFailure.origin: FailureOrigin::{Provider, Transport, GatewayDeadline}` captured before a bounded refusal-body await. A provider response is retained through a later cancellation without starting another hop; a local deadline never becomes provider quota evidence. `RoutingHost::wait` returns `WaitOutcome { elapsed_ms, result }` from the host's actual monotonic clock, including cancellation. `RoutingSession::elapsed_wait_ms()` accumulates that observation before propagating the original error; `WaitBudget.waited_ms` remains the planned cap. The Worker owns deferred producer cancellation and late-response cleanup.

Unresolved owned boundaries at the initial freeze are native pool publication/refresh (m06) and Claude strong proof/roster capabilities (m03/m12). Missing capabilities fail closed until those exact owners provide them; the source parser alone never authorizes a write or refresh. These remain original-goal work, not excluded functionality. Shared manifests/lock, platform adapter and other crates remain controller/owner paths.

Extras use `begin_extras` followed by one `AdmissionHandle`; every image child is registered before spawning, while sequential Voyage and SystemOne work retain one open child scope. One dispatch ticket owns API accounting for the original request. Child completion cannot refund a started sibling, finish the original kernel or manufacture a paid continuation. The aggregate owner supplies the source kernel disposition separately from semantic and delivery observations; embedding-job polls only release kernel admission. `prepare_image_child`, `before_image_dispatch` and `image_refusal` use Codex-only account/current-publication fences and preserve the source logical child request IDs.

Paid credentials carry provider, owner ID/epoch, configuration generation and credential binding from the current owned host capability. The exact server-normalized logical request, endpoint surface and pinned synthetic hop obtain the authority receipt; its protected metadata must match that capability before reserve_paid. Client synthetic flags and transformed wire model aliases never authorize the reservation. The host rechecks that owned capability immediately before transport.
